网络应用位于计算机网络体系结构的最上层，是设计和建立计算机网络的最终目的，也是计算机网络中发展最快的部分。

# 1\. 应用层概述

开发一种新的网络应用首先要考虑的问题就是网络应用程序在各种端系统上的组织方式和它们之间的关系，即网络应用程序体系结构。  

主流的网络应用程序体系结构有 3 种： 客户/服务器（C/S）体系结构， 对等（P2P）体系结构，混合结构（Hybrid）

**客户/服务器**（C/S）体系结构包括一个总是运行着的服务器程序和许多有时运行的客户程序。客户进程是服务请求方，服务器进程是服务提供方。服务器进程具有固定端口号，而运行服务器程序的主机也具有固定的 IP 地址。

![JtSiearb\.png](JtSiearb.png)

---

**对等**（P2P）体系结构中，没有固定的服务请求者和服务提供者，分布在网络中的应用进程是对等的，被称为对等方。对等方相互直接通信，每个对等方既是服务的请求者，又是服务的提供者。

![hrMLXiYI\.png](hrMLXiYI.png)

---

混合结构（Hybrid）是 C/S 和 P2P 的结合体。

# 2\. 域名系统 DNS

DNS 为其他各种网络应用提供一种核心服务，【域名\<\-\-\-\>IP 地址】 的转换。互联网的 DNS 是一个联机分布式数据库，采用 C/S 体系结构。

域名到 IP 地址的转换叫做域名解析。此过程由若干个域名服务器程序完成的。

IP 地址到域名的转换叫做反向域名解析。

DNS 允许多台主机（多 IP 地址）使用同一个域名，实现负载分配。

## 2\.2\. 域名服务器

域名和 IP 地址的映射关系必须保存在计算机中，以便供所有其他应用查询。DNS 的方法是将域名信息分布到叫作域名服务器的许多计算机上。

为什么要多个？

![PGo1mM43\.png](PGo1mM43.png)

根域名服务器：最高层次的域名服务器。根域名服务器并不直接管辖域名信息，它知道所有的顶级域名服务器的域名及其 IP 地址。它负责将域名解析任务进行分配。互联网一共有 13 个跟域名服务器。

顶级域名服务器：负责管理在该顶级域名服务器注册的所有二级域名。当收到 DNS 查询请求时，顶级域名服务器就给出相应的回答，可能是最后的结果，也可能是下一级权威域名服务器的 IP 地址。

权威域名服务器：负责管理某个区的域名服务器。

本地域名服务器：不属于域名服务器等级结构。是为了减少域名请求数量而搭建的缓存服务器，用于缓存经常使用的域名和 IP地址的映射关系。每一个 ISP，每一个大学，甚至一个大学里的每一个系，都可以拥有一个本地域名服务器。你也可以将自己的电脑安装上 DNS 应用软件充当本地域名服务器。

# 3\. 万维网

万维网（World Wide Web，WWW）是一个大规模的、联机式的信息储藏所，是运行在互联网上的一个分布式应用，简称 Web。万维网利用网页之间的链接（或称超链接）将不同网站的网页链接成一张逻辑上的信息网，从而方便的从互联网上的一个站点访问另一个站点。

![hs8ifXpc\.png](hs8ifXpc.png)

万维网是一个分布式的超媒体（Hypermedia）系统，它是超文本（Hypertext）系统的扩充。 超文本就是带有链接的文本，超媒体与超文本的区别是文档内容不同。超文本文档仅包含文本信息，而超媒体文档还包含其他多媒体对象，如图形、图像、声音、动画，甚至视频。

万维网使用统一资源定位符（ Uniform Resource Locator， URL）来标志万维网上的各种文档，并使每一个文档在整个互联网的范围内具有唯一的 URL。

超文本传送协议（HyperText Transfer Protocol，HTTP）实现浏览器和万维网服务器间的文档请求和响应。

超文本标记语言（HyperText Markup Language， HTML） 用于在万维网文档中写入超链接，制作出来的页面能够在任何浏览器的窗口中显示。  

搜索引擎用于在万维网上查找信息。

## 3\.1\. HTTP 协议

HTTP 定义了浏览器怎样向万维网服务器请求万维网文档，以及万维网服务器怎样把万维网文档传送给浏览器。

![Fq1T5GkL\.png](Fq1T5GkL.png)

每个万维网网站都有一个服务器进程，它不断地监听 80 端口。 一旦监听到连接建立请求并建立 TCP 连接，浏览器就向万维网服务器发出浏览某个页面的请求，服务器返回所请求的页面作为响应。  

点击这个网址后 http://www\.tsinghua\.edu\.cn/yxsz\.htm ：

- 浏览器向 DNS 请求解析 www\.tsinghua\.edu\.cn 的 IP 地址。

- DNS 解析出清华大学服务器 IP 地址为 166\.111\.4\.100。

- 浏览器与服务器建立 TCP 连接，端口为 80\.

- 浏览器发出取文件命令：GET/yxsz\.html 。 

- 服务器把 yxsz\.html 发给浏览器。

- 释放 TCP

- 浏览器显示 HTML 文件内容。

# 5\. 文件传输协议 FTP

FTP 提供交互式的访问，允许客户指明文件的类型与格式，并允许文件具有存取权限。

FTP基于客户/服务器体系结构。一个 FTP 服务器进程可同时为多个客户进程提供服务。  FTP 的服务器进程由两大部分组成：

- 主进程：负责接受新的请求

    - 打开熟知端口 21，使客户进程能够连接上服务器进程  

    - 等待客户进程发出连接请求  

    - 启动从属进程来处理客户进程发来的请求。  

    - 回到等待状态，继续接受其他客户进程发来的请求。  

- 从属进程：负责处理单个请求，其内部又分**控制进程**和**数据传送**进程  

    - 控制连接在整个会话期间一直保持打开，控制连接用于传送客户端发出的各种命令

    - 数据连接负责传输文件数据。数据连接是以 20 端口新建立的 TCP 连接。

# 7\. 动态主机配置协议 DHCP

动态主机配置协议（Dynamic Host Configuration Protocol， DHCP ）运行一台计算机加入新网络时自动获取 IP地址、子网掩码、默认网关、DNS 服务器地址等 IP 配置信息。 

需要自动获取 IP 地址的主机（DHCP 客户），使用 UDP 向网络发送 DHCP 发现报文，目的 IP 地址为 255\.255\.255\.255，广播此报文。源 IP 地址为 0\.0\.0\.0 。DHCP 服务器会对该报文进行应答，发送提供报文。

DHCP 服务器查找自身数据库，匹配源报文中的 MAC 地址，查找配置信息。若找不到，从 IP 地址池中取一个 IP 地址进行分配。

DHCP 客户可能收到多个 DHCP 服务器的应答，选择其中一个发送请求报文，表示正式的请求。提供该信息的 DHCP 服务器会做出确认报文回应。

DHCP 服务器端口号是 67         DHCP 客户端口号是 68。

# 8\. P2P 文件共享

文件共享两个主要问题：如何找到文件？如何从拥有该文件的主机下载？

在P2P对等方中搜索对象  

- 集中式目录

    - 提供一个集中式目录服务器，该目录服务器保存所有对等方的 IP 地址及其共享文件的名称。 这是典型的客户服务器方式。索引存于服务器，下载是 P2P。

- 查询洪泛

    - 把所有对等方组织成一个逻辑的网络，称为覆盖网络。节点为对等方，边为 TCP 连接。一个对等方要查找某个文件时，会向这个覆盖网络中的所有相邻对等方进行洪泛法查询。  

- 分布式散列表

    - 查询洪泛的优化，该覆盖网络中可以将要查找的对象可靠地映射到网络中的特定结点， 并且能有效路由到该结点。通过哈希函数进行确定的关系计算。

---

文件分发

在 P2P 文件分发中，每个对等方都能在收到文件后再将该文件分发给其余对等方，从而协助进行分发，这样就大大缩短了文件分发的时间。

# 9\. 多媒体网络应用

**多媒体网络应用分类**

- 流式存储音/视频：播放存储在服务器上的文件。“流式”指可以边下载边播放。

- 流式实况音/视频：直播，网络电视。可以和现场有些许时间延迟

- 实时交互音/视频：网络视频会议。

**挑战及其措施**

音/视频压缩：较少传输数据量

延时抖动消除：发送速率恒定，但接收不恒定。通过缓存保证播放的内容不产生延时抖动

丢失分组恢复：实时流媒体倾向恢复数据方式来重建丢失分组，通过分组交织技术减小分组丢失的影响。

**实时传输协议**

TCP 不适合传输实时数据，而 UDP 又缺少相应机制。**实时传输协议 RTP** 在 UDP 的基础上提供了序号、时间戳等机制，与 RTPC 协议一起完成实时数据传输。**实时传输控制协议RTPC **提供监视、反馈、媒体间同步等功能。
